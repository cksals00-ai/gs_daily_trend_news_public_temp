## §2【버그】취소 수치가 예약보다 크다 — 판정 결과

### 결론
1. **진짜 버그는 따로 있었다 — raw_db 파일 간 이중 계상.** 예약·취소 모두 15~18% 부풀려져 있었다. 수정함.
2. **취소 > 예약 자체는 버그가 아니다.** 27/43과 28/44는 서로 겹치지 않는 별개 모집단이다. 원인후보 (1) 이중계상은 사실이 아니고, (2) 기간필터 없음 + (3) 모집단 분리가 원인이다. 기존 "27은 이미 net, 28을 차감하면 이중차감" 전제는 **맞다**.

### 근거 1 — 파일 간 이중 계상 (수정 대상이었던 실제 버그)
시트 코드 463개에 걸린 원시행을 파일별로 집계:

| 파일 | 행수 | RN |
|---|---:|---:|
| 2026 / 27 스냅샷(_20260820_생성시간) | 25,608 | 25,659 |
| 2026 / 27 재전송(20260101-20260630) | 22,618 | 22,650 |
| 2026 / 27 재전송(20260701-20260731) | 8,835 | 8,845 |
| 2026 / 28 스냅샷 | 19,952 | 19,988 |
| 2026 / 28 재전송(20260101-20260630) | 14,138 | 14,171 |
| 2026 / 28 재전송(20260701-20260731) | 7,601 | 7,614 |

동일 예약(판매일자·영업장·이용자명·입실·퇴실·1박객실료·객실수·최초입력일시 복합키)이 **몇 개 파일에 등장하는지** 분포:

- 예약 27/43 — 고유 48,220건 중 **8,827건이 `스냅샷` + `재전송(0701-0731)` 두 파일에 중복 등장**
- 취소 28/44 — 고유 34,130건 중 **7,601건이 동일하게 중복 등장** (7월 재전송 행 전부)

즉 7월 재전송 파일은 스냅샷에 이미 통째로 포함돼 있는데 기존 코드는 두 파일을 모두 더하고 있었다.

**수정**: `parse_raw_db.py`가 쓰는 규칙(판매일자 월 경계로 재전송 ≤N월 / 스냅샷 ≥N+1월 분리)을 `action_plan_perf.py`에 이식(`plan_files()`), 파일 내 동일행 해시 중복제거 추가. macOS 파일명이 NFD라 `재전송`·`생성시간` 매칭 전 NFC 정규화 필수.

수정 효과(2026-08-20 시트 기준 동일 조건 비교): 총 RN 57,174 → **48,326 (−15.5%)**, 총 매출 138.99억 → **115.66억 (−16.8%)**, ADR 243,098 → 239,332.

### 근거 2 — 27과 28은 별개 모집단 (취소 > 예약이 정상인 이유)
- 2026 예약상태 분포: **27/43 = 퇴실 46,507 · 예약 10,059 · 투숙 319 · 노쇼 176 (취소 0건)** / **28/44 = 취소 41,691 (전량)**
- 예약 고유키 47,656 vs 취소 고유키 31,944 → **교집합 1,923건(취소의 6.0%)** 뿐. 이 6%는 취소 후 같은 조건으로 재예약된 건으로 보인다.
- 따라서 27에는 취소분이 애초에 들어있지 않다(= 이미 net). 28을 빼면 이중차감이 맞다.

### 근거 3 — 기간필터 없음이 취소를 더 키운다
예: 코드 86158887 취소행의 입실월 분포 = 202607: 134 / 202608: 87 / 202609: 10.
캠페인(7/1~7/7) 종료 후 8·9월 투숙분 취소까지 합산된다. 인플4팀 행은 수정 후 실적 2,530RN / 취소 3,307RN.

### 반영
- `parse_txt()` 도크스트링에 "예약=이미 net, 취소=별개 모집단·차감 금지" 명시.
- 산출 JSON `meta.cancel_note` / `meta.dedupe_note` 추가.
- 화면 표 헤더를 **`취소(참고)`** 로 바꾸고, 하단 주석에 "예약은 이미 취소 제외분이라 차감하지 않음" 명시.
- 취소 열은 제거하지 않고 참고치로 유지(진단 가치가 있음).

## §1 테이블 탭 KPI 9칸 — 처리 결과

- **실적 3칸(RNS·ADR·REV)**: 채워짐. 메인시트(gid=1818134248) 486행 중 **60행**.
- **크로스시트 매칭**: 요청서의 (1)번안 `사업장 + 채널 + 판매기간` 조합매칭 채택.
  실제 구현은 **사업장 + 판매시작일 완전일치 → 후보가 여럿이면 인플루언서명이 채널 문자열에 포함되는 행으로 압축 → 그래도 못 좁히면 미채움**(추정 금지).
  인플루언서 시트 126행 중 **55행(44%)** 확정 연결, **71행 미매칭**.
  · 허용오차 ±3일까지 넓혀도 49%에 그치고 모호 후보만 7 → 19건으로 늘어 채택하지 않았다.
  · 매칭률이 낮은 이유: 인플루언서 시트의 `시작일`이 판매시작일이 아니라 촬영/노출일인 행이 많다.
  · **건의**: 요청서 (2)번안(메인시트 Key ↔ 인플루언서시트 Key열)이 필요하다. 박찬민 확인 요청.
- **목표·달성률 6칸: 채울 수 없음 — 코드 문제가 아니라 원천 값 부재.**
  메인시트 `KPI (객실수 실)`·`KPI 매출 (백만원)` 열이 **486행 중 1행만** 입력돼 있다.
  배선은 완료했으므로(`mapRow()`에서 `kpi.rns_target`/`rev_target`에 연결) **시트에 목표값을 넣으면 즉시 표시된다.**
  그 전까지는 규칙대로 `—` 유지.
