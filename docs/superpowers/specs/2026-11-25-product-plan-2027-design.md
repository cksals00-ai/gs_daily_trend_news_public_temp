# 2027 상품기획 · 상품상세 심층화 설계 (v1)

작성 2026-11-25 · 대외비·관리자용 · 상태: 승인(설계) → 구현 계획 단계

## 1. 목적과 산출물

2027년 GS 상품(패키지) 기획을 데이터로 뒷받침한다. 최종 산출물은
**"2027년 언제 · 어느 채널에서 · 어느 상품(구성)을 · 어느 사업장에 · 얼마의 비용으로 팔아 · 어떤 수익"**
을 행 단위로 담은 기획 매트릭스이며, `docs/product-detail.html`(상품상세)에 통합하고 엑셀로 내려받을 수 있게 한다.

세 가지 입력을 종합한다.
1. 내부 로우데이터(`data/raw_db`) — 1순위. 현재 뎁스 1(연·월·사업장→카테고리 9종)을 뎁스 5~6으로 심층화
2. 웹애널리틱스(GA4 속성 433673272 소노호텔앤리조트 통합) — 홈페이지 상품별 판매·채널·요일
3. 외부 시장 — 경쟁사 패키지 구성·가격·판매기간, 광고(후순위)

## 2. 확정 전제 (변경 시 스펙 개정)

| 항목 | 결정 | 근거 |
|---|---|---|
| 판정 기준 | **비수기 주중(요금시즌 41) 객실매출 증분**이 1순위. 가드레일 ① 상품 ADR ≥ 같은 사업장·같은 요금시즌의 전년 ADR ② 주말→주중 이동분(카니벌) 제외 | 사용자 위임, 2026-11-25 |
| 비용 축 | 보류. **수수료만 실측**, 광고비·굿즈 원가·기획전 집행비는 입력칸(빈칸) | 사용자 "비용은 일단 패스" |
| 매출 정본 수식 | 객실매출 = 1박객실료 × 객실수 ÷ 1.1 (VAT 제외). 패키지도 동일 | 앵커 검증: 비발디벨 온가을PKG(86150059) 2025-10 raw 126행·Σ1박객실료 20,303,000 = 실적 트래커 126 RNTs·REV 20,303,000 정확 일치 |
| 상품 식별자 | **회원번호 86xxxxxxxx = 상품코드**(사업장 × 채널군 × 패키지 1코드). 기획전 = 코드 묶음 | 트래커 `패키지코드` 시트 구조와 raw 동일 |
| 구성가치 | (PKG패키지총금액 − PKG객실) ÷ 1.1. PKG 필드는 예약 단위 값이 박수만큼 반복되므로 **KEY_RSV_NO로 중복 제거** 후 합산 | 캄제주 2박 샘플: PKG객실 480,000 = 2 × 240,000 |
| Net 처리 | 27 재전송 파일 = 현재 유효 예약(취소 제외). **큐브는 27만 사용.** 28은 취소율·리드타임 보조 분석에만 | 앵커: raw(최종) 108 < 10/27 스냅샷 114 (스냅샷 이후 취소분 소실) |
| 분석 기간 | 2023~2026 (2022는 옵션 플래그) | |
| 제외 | 팔라티움·오션월드빌리지(기존 GS 리포트 규칙과 동일) | |
| 출처 표기 | 산출물에 소스 출처 표현 금지, 「대외비·관리자용」 표기 | 운영 규칙 |

## 3. 접근 방식

독립 **상품 큐브 빌더**를 신설하고 페이지는 큐브만 읽는다(2안). 기존 `parse_raw_db.py`·`build.py`·`db_aggregated`는 손대지 않는다.
- 1안(기존 product_detail 확장)은 모놀리식·전체 재빌드 50분·회귀 위험으로 제외
- 3안(campaign_history 확장)은 요금시즌·요일·구성가치·리드타임이 없어 주중/ADR 분석 불가로 제외

## 4. 구성요소

### 4.1 `scripts/build_product_cube.py` (신규)
입력: `data/raw_db/{2023..2026}/27*.txt` (cp949, `;`, 57열). 2026은 최신 재전송 1개(스냅샷 제외).
대상 행: 회원번호 86으로 시작 + GS 세그 코드(변경예약집계코드 ∈ {A4, A5, 53, 72, 58}) + 제외 사업장 필터.

출력 `docs/data/product_cube.json` (+ `.gz` 동반 생성, 크기 ≥ 3MB면 페이지는 gz 경로 사용):
```
meta        {built, years, base_date, rows_parsed, rules}
dims        {seasons:{41:"비수기 주중",42:"비수기 주말(토)",43:"비수기 주말(금)",11:"성수기 주중",12:"성수기 주말(토)",14:"성수기 주말(금)",13:"연휴",30:"연휴"},
             properties:[display명 "01.벨비발디"…], agents:[…], categories:[9종]}
codes       { "86150059": {
               name, series(정규화 상품명), campaign, category, prop(display), seg(OTA|G-OTA|Inbound),
               chan_class(OTA|GOTA|직불|네이버|쿠팡|회원|D멤버스|기타), comm_rate(실측 수수료/총액 중앙값),
               by_ym: { "202510": { s:{ "41":[rn, rev, comp, comm, bk], "43":[…] },   # rev/comp/comm 원 단위 VAT제외 정수
                                     dow:[일,월,화,수,목,금,토 RN], lead:{p50,p90,mean} } },
               rt: { 객실타입코드:[rn, rev] },          # 상위 N
               ag: { AGENT명:[rn, rev] } } }
campaigns   { 기획전명: { codes:[…], props:[…], category, composition:{auto:{식음,부대,스포츠,아쿠아,기타 금액비중}, text},
                        sale_window:{from,to}(최초입력일자 p05~p95), stay_window:{from,to},
                        by_year:{ "2025":{rn, rev, comp, comm, adr, weekday_share} } } }
baseline    { prop: { year: { season: {rn, rev, adr} } } }   # 전 GS 세그 기준 ADR 가드레일·주중비중 분모
```
상품 계층: 코드 → `series`(기존 `parse_package_trend.normalize_series` 재사용) → `campaign`(규칙: ① `data/product_campaign_map.json` 수기 매핑 우선 ② 같은 series + 판매기간 겹침 자동 묶음) → `category`(기존 `classify_v4`).
`data/product_campaign_map.json`: {campaign명: {codes:[], composition_text, note}} — 트래커 4종(온PKG·사우나PKG·2연박·키즈브릭) 코드를 초기 등록.

### 4.2 `scripts/fetch_ga4.py` 확장 (2차)
`sections.items`: itemName × itemCategory × 월 — itemsPurchased·itemRevenue, 2024-01~ 전 기간.
`sections.items_dow`: dayOfWeek × ecommercePurchases. 기존 섹션 무변경.
매핑: itemCategory → 사업장(기존 `_property_key`), itemName 정규화 → 큐브 `series`/`campaign` 조인(매칭 사전 `data/ga4_item_map.json`, 미매칭은 '기타'로 남김·추정 금지).
실행은 호스트(자격증명 env)에서; 스크립트 수정 후 1회 수동 실행 또는 `host_daily_crawl.sh` 자동.

### 4.3 외부 시장 (3차 · 최소 범위)
`sono-competitor-crawler` 최신 가격 CSV의 `객실유형` 문자열 → `scripts/parse_competitor_packages.py` → `docs/data/competitor_packages.json`
{brand, 경쟁사명, 소노사업장(매칭), package_name, inclusions(키워드: 조식·사우나·스키·워터파크·와인·굿즈…), price_min/max, seen_from/to}.
광고 수집(Meta Ad Library·네이버 검색광고)은 인증 필요 → 별도 승인 후. 공식홈 수집기 확장(용평·오크밸리·아난티·롯데리조트)은 범위 밖.

### 4.4 `docs/product-detail.html` 확장
기존 SEC0~SEC7 유지. 추가:
- **SEC8 상품 드릴(뎁스 6)**: 연도 → 사업장(권역) → 카테고리 → 기획전 → 상품코드/채널 → 투숙월 × 요금시즌·요일 → 객실타입. 브레드크럼 + 표. 레벨 공통 지표: RN · ADR · 객실매출 · 구성가치 · 수수료율 · 주중비중 · 전년비 · 평균 리드타임 · 홈페이지 비중(GA4, 2차).
- **SEC9 사업장별 상품 분석 매트릭스** — 사용자 예시 양식 고정:
  `구분 | 전략 상품(2027Y·2026Y·2025Y) | 상품 구성(2027Y·2026Y·2025Y) | 판매일자(2027Y·2026Y·2025Y) | 판매 실적 2027Y(목표) RNs·REV · 2026Y RNs·REV · 2025Y RNs·REV | 비고`
  행 = 전사업장(전채널 기획전) + 사업장별. 2025Y·2026Y는 큐브 `campaigns`가 자동 채움(판매일자=sale_window, 구성=composition.text 또는 auto). 2027Y는 1차에서 빈칸, 2차에서 기획 매트릭스로 채움. **📥 엑셀 다운로드**(열 구조 동일, 시트 1장 + 상세 시트 1장).
- **SEC10 2027 기획 매트릭스**(2차): `언제(판매기간·투숙기간) | 채널 | 상품(구성) | 사업장 | 목표 RN·ADR·REV | 수수료(실측률) | 비용(입력) | 예상 공헌(REV−수수료−비용) | 근거`. **📥 엑셀 다운로드**.
- 엑셀은 클라이언트 생성(SheetJS, cdnjs 고정 버전) — 필터 상태 반영. 기존 페이지에 서버 xlsx 방식이 있으면 그 방식을 따른다(구현 계획에서 확정).
- 인증 executive, 네비·캐시버스터 규칙 기존대로. 뎁스 깊은 표는 가로 스크롤 허용, 모바일은 상위 3레벨만.

### 4.5 2027 기획 매트릭스 산출 로직 (2차)
- 후보 = 2025~2026 기획전 × 사업장 × 투숙월 실적 중 ① 주중(41) RN 기여 상위 ② 가드레일 ADR 통과 ③ 카니벌 체크(기획전 기간 주말 RN이 전년 대비 감소하지 않음)
- 배치 = 전년 `sale_window`·`stay_window` + 리드타임 분포를 2027 달력에 투영(요일 정렬)
- 목표 = 전년 실적 × 2027 예산 성장률(`generate_otb_data.load_budget_2027` 사업장×세그×월)
- 채널 믹스 = 코드별 실적 비중. 구성 제안 = 같은 사업장·시즌 내 상품 간 구성가치 ↔ ADR·RN 비교(상관이 아닌 순위·차이로 표기)
- 데이터가 없는 칸(비용, 신규 상품 수익)은 빈칸 또는 '가정' 라벨. **추정치를 실적처럼 표기하지 않는다.**
